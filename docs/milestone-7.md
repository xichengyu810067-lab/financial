# 里程碑 7：發票與自動化記帳（第一批）— 規格

討論日期：2026-11-18。目標：少打字。掃紙本發票、匯入載具消費明細、固定支出到期提醒，都先進「待確認匣」，確認後才入帳；結帳時可以直接秀手機條碼。

完成定義：掃一張電子發票就能入帳（可拆品項到不同類別）；上傳一個月的載具明細檔，重複的發票不會記兩次；房租這類固定支出到期會出現在待確認匣；設定過的手機條碼能在 App 裡秀給店員掃。

## 已確認的決策

| 項目 | 決定 |
|---|---|
| 範圍 | 掃發票 QR Code、匯入載具明細檔、固定支出、顯示手機條碼。**載具自動同步（財政部 API）暫不做**，等使用者向財政部確認個人能否申請 API 後再決議 |
| 掃完之後 | **兩種都要**：單張掃描直接開確認面板並填好；切到「連續掃描」模式則一張張放進待確認匣 |
| 多品項發票 | **可以拆成多筆**：預設一張發票一筆（總額），確認時可把品項分到不同類別，各自成為一筆交易 |
| 固定支出到期 | **放進待確認匣**，點一下入帳；金額會變的（電費）可以先改 |
| 店名 | QR Code 只有賣方統編：**用統編查經濟部公開的商業登記資料取得店名並記住**（只送出店家統編，不含使用者資料） |
| 自動分類 | **兩種都要**：先看使用者自訂的規則（店名包含某字 → 類別／付款帳戶），沒有規則再照「同一家店上次記到哪」猜；都沒有就留空讓使用者選 |
| 手機條碼 | **存在帳號裡**（`profiles`，受 RLS 保護），換裝置也看得到；只存條碼本身，**不存驗證碼** |
| 待確認匣位置 | **今天這一頁上方提醒＋獨立頁面 `/inbox`**；「更多」選單也有入口 |

## 資料模型（新 migration）

- `profiles.carrier_barcode text`：手機條碼，格式 `/` 加 7 碼（數字、大寫英文、`+`、`-`、`.`），check constraint 驗證。
- `inbox_items`（待確認項目）
  - `ledger_id`、`source`（`invoice_qr`／`invoice_csv`／`recurring`）、`status`（`pending`／`confirmed`／`dismissed`）
  - `entry_date`、`amount`、`merchant_name`、`seller_ban`（賣方統編）、`invoice_no`、`items jsonb`（品名、數量、單價）
  - `suggested_category_id`、`suggested_account_id`、`memo`、`recurring_rule_id`、`due_date`
  - unique `(ledger_id, invoice_no)`（發票去重）、unique `(recurring_rule_id, due_date)`（固定支出不重複產生）
- `entries.invoice_no text`（可空，非 unique；拆成多筆時同一張發票會有多筆交易），加索引供去重查詢。
- `merchants`（每本帳本的店家記憶）：`seller_ban`、`name`、`last_category_id`、`last_account_id`、`updated_at`；確認入帳時更新。
- `category_rules`：`pattern`（店名包含）、`category_id`、`account_id`（可空）、`sort_order`；依序比對，第一條符合的生效。
- `recurring_rules`：`name`、`kind`（支出／收入／轉帳）、`amount`、`from_account_id`／`to_account_id`／`category_id`、`memo`、`frequency`（每月第 N 天／每週星期幾／每年某月某日）、`next_date`、`amount_varies`（金額會變，確認前提醒改）、`is_active`。
- 全部新表照既有做法：RLS 用 `is_ledger_owner`、跨帳本參照用 trigger 擋、RLS 自動測試補上新表。

## RPC

- `confirm_inbox_item(p_item uuid, p_splits jsonb)`：一次交易裡依 `p_splits`（每筆：類別、帳戶、金額、備註）呼叫既有的分錄邏輯建立一到多筆交易，拆分金額合計必須等於項目金額；標記項目 `confirmed`、更新 `merchants`。
- `generate_recurring_items(p_ledger uuid, p_until date)`：把到期（`next_date <= p_until`）的固定支出產生成待確認項目並推進 `next_date`；可重複呼叫不會多產生（靠 unique）。**不需要伺服器排程**：打開今天這一頁時呼叫一次，錯過的期數會補上。
- 統編查店名：Next.js Route Handler 代查經濟部公開資料（瀏覽器直接查會被跨網域擋），結果存進 `merchants`，同統編不再查。

## 畫面

- **掃描**：「記一筆」旁多一個「掃發票」。開相機掃左右兩個 QR Code（Safari 沒有內建條碼辨識，要用 zxing 之類的函式庫）；沒有相機的電腦可以上傳發票照片辨識。
  - 單張模式：掃完開確認面板，金額、日期、店名、品項都填好，類別與付款帳戶依自動分類預選；可「拆成多筆」把品項分到不同類別。
  - 連續模式：每掃一張就放進待確認匣，畫面顯示已掃張數；重複的發票提示「這張已經記過了」。
- **待確認匣 `/inbox`**：依日期列出，每筆可確認、修改後確認、略過；可勾選多筆一次確認（只限已有類別與帳戶的）。今天這一頁上方顯示「N 筆待確認」。
- **匯入載具明細**：設定頁或待確認匣上傳檔案 → 解析 → 摘要（幾張發票、幾張重複略過、日期範圍）→ 放進待確認匣。
- **固定支出**：設定頁（或獨立頁）管理清單：新增、修改、暫停、刪除；顯示下次日期。
- **手機條碼**：設定頁輸入並驗證格式；任一頁的「更多」選單與待確認匣有「出示手機條碼」，全螢幕顯示 Code 39 條碼（白底、加亮度提示），方便店員掃。
- **自動分類規則**：設定頁一張卡，列出規則、新增「店名包含 ___ → 類別 ___（付款帳戶 ___）」、排序。

## 待確認事項（實作前）

1. **載具明細檔範例**：請從財政部電子發票整合服務平台下載一份自己的載具消費明細檔給我（可以把金額以外的敏感內容改掉），解析器照實際格式寫，不憑印象。
2. **QR Code 欄位位置**：照財政部「電子發票證明聯二維條碼規格」官方文件實作與寫測試（發票號碼、民國日期、隨機碼、銷售額與總計額、統編、品目、編碼參數），實作時再核對一次版本。
3. **統編查詢來源**：實作時確認經濟部商工登記公開資料 API 的網址、使用條款與查詢頻率限制；公司與行號（商業登記）可能是不同端點。
4. 載具自動同步：使用者向財政部確認後再決定是否開里程碑。

## 不在此里程碑
